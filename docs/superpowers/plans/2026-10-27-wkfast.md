# WKFast Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the approved minimal mobile WaniKani review app.

**Architecture:** A static Preact/HTM application calls WaniKani directly. A pure review reducer owns per-item progress; an API client loads assignments and saves completed reviews. State and credentials stay in memory.

**Tech Stack:** Preact, HTM, npm for installation, Node's built-in test runner. No build step.

**Spec:** `docs/superpowers/specs/2026-10-27-wkfast-design.md`

## Global Constraints

- No backend, database, browser persistence, or third-party scripts.
- Accept the key exclusively through `?api_key=…`, retaining it in the URL for refresh. No key-entry form or login flow.
- Self-grade meanings; automatically check readings with a two-tap kana keypad.
- Snooze excludes the whole item for this session without a write.
- Submit only completed reviews, including meaning and reading mistake counts.
- User authorized working directly in this new repository and starting implementation.

## Review Focus

- A timeout after a successful POST must not cause a duplicate submission.
- Radicals with no text require an image without revealing the meaning.
- Double taps must not skip a review or duplicate a POST.
- Small kana, voiced kana, Unicode variants, and nonaccepted kanji readings must behave correctly.
- Failed page loads must not silently start a partial review session.
